<a id="use-cases"></a>

## Less repeated formatting, clearer projects

This skill preserves a layout developed for the author's repositories. Codex starts with that structure, then adapts the content, assets and claims to the actual project.

| What gets in the way | How the skill helps |
| --- | --- |
| Repeating the same layout instructions for each repository | Keeps the section order, artwork position, navigation and footer. |
| A complete Chinese README but only a short English summary | Provides separate Chinese and English templates with matching hierarchy and facts. |
| Attractive images with a buried starting point | Puts use cases, results and quick start before advanced configuration. |
| Different projects need different presentation | Allows sections to be removed and artwork or colors to change with the topic. |

<a id="quick-start"></a>

## Install, then describe the task

Send this request to Codex:

```text
Install the skill from this GitHub repository:
https://github.com/TUANZIDING/github-homepage-style/tree/main/skills/github-homepage-style
```

After installation, use it in the next turn:

```text
Use $github-homepage-style to organize this repository homepage.
Keep the actual features and working commands, and provide complete Chinese and English homepages.
```

Alternatively, download the [skill package](https://github.com/TUANZIDING/github-homepage-style/releases/latest) and place its `github-homepage-style` directory in `${CODEX_HOME:-$HOME/.codex}/skills/`. If the skill already exists, compare versions and preserve your edits before updating it.

[Chinese installation guide](使用指南v1.0.md). The distributable contains the skill itself; the author's global settings and memory files are excluded.

<a id="workflow"></a>

## Read the project, then arrange the layout

**Read the repository → Keep useful sections → Replace template fields → Align both languages → Check links and facts → Publish when authorized for the task**

| Your decision | How Codex uses it |
| --- | --- |
| Project purpose and audience | Reads the current README and documentation first. |
| Whether to use this structure | Applies wide artwork, centered titles, navigation, paired examples and concise tables. |
| Available assets and features | Omits unsupported sections and distinguishes concepts, screenshots and results. |
| Whether to publish | Installation or invocation alone does not authorize publication. |

<a id="capabilities"></a>

## Capability status

| Status | Included | Limits |
| --- | --- | --- |
| Provided | Skill instructions, layout specification, bilingual templates, baseline and provenance | Template fields must be replaced for the target repository. |
| Package checks | File digests, skill references, bilingual navigation, documentation links and portable paths | Passing checks does not establish the target project's functionality. |
| Executed by Codex | Reads, edits and organizes a repository homepage | It is not a standalone site generator and does not guarantee identical output. |
| Task dependent | Artwork generation, screenshots, commits and publication | Requires the appropriate tools, materials and current task authorization. |

<details>
<summary><strong>Set it as your default</strong></summary>

After installation, you may add this preference to your own Codex global `AGENTS.md`:

```text
When organizing a GitHub repository homepage, use the github-homepage-style skill by default.
Keep its structure and adapt images, colors and sections to the project.
The current task's explicit requirements take priority.
```

This is optional. The package does not include the author's global configuration or rewrite another user's settings.

</details>
