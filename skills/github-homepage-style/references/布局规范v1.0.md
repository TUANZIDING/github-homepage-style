# 个人GitHub首页布局规范 v1.0

保存日期：2026-10-10。用户明确选用念景v0.2.1的GitHub介绍结构作为以后仓库首页的默认参考。

## 信息顺序

| 顺序 | 模块 | 排版与内容 |
| --- | --- | --- |
| 1 | 宽幅主图 | 首屏放一张主题明确的横图，`img width="100%"`；优先无文字或少文字的主视觉。念景案例比例约2.4:1，可随素材调整。 |
| 2 | 居中标题与定位 | `h1 align="center"`显示中文名与英文名；双语短标语，一两句话说明适用对象。 |
| 3 | 语言与状态 | 中文 / English入口置于首屏。只放已存在的Release、CI与实际许可证徽章，通常两三个即可。 |
| 4 | 短标签与导航 | 用三四个`code`短标签概括特点；用锚点进入场景、成果、快速开始、能力和贡献。 |
| 5 | 使用场景 | 用具体用户需求说明价值，简短表格即可。有合适素材时放第二张辅助主图。 |
| 6 | 成果展示 | 两列排布图像、视频或真实成果入口。没有可展示成果时省略，不用概念图充当结果。 |
| 7 | 快速开始 | 最短可执行路径，明确环境与打开入口；完整安装文档另设链接。截图可用两列中英文对照。 |
| 8 | 工作流 | 一行箭头或简短流程图，再用“想做什么 / 怎样实现”的表格解释。 |
| 9 | 能力状态 | 区分已实现、已验证、离线适配、计划与外部入口，状态由当前证据决定。 |
| 10 | 技术配置 | 可选；用`details`折叠，首页不堆积完整API参数或运维教程。 |
| 11 | 共创与文档 | 贡献方向、语言要求、文档索引、问题入口，通常合成一个简明区域。 |
| 12 | 页脚 | 居中维护者、许可与素材来源，必要边界用一小段文字说明。 |

这是默认顺序，可根据项目用途删减。数据集、医学研究、课程和开发工具的功能与证据要求各不相同，不能复用念景的具体能力声明。

## 视觉节奏

- 整体以宽幅封面、居中首屏、短段落、留白、双列画廊和表格为主。避免把首页写成连续的长说明书。
- 采用GitHub可保留的Markdown、`p`、`h1`、`img`、`a`、`details`及`summary`；不依赖CSS、脚本、隐藏组件或页面主题修改。
- 两列适用于图像和并列成果；多列可能在窄视口难读。标题、数字、命令和导航保留为可读文字。
- 念景的案例主题是米白手工纸、墨线、暖金和低饱和蓝。其他仓库用适合内容的主图与颜色，但保留布局秩序。
- 新主图注明概念、AI生成或素材出处；真实应用截图标为截图，既有外部作品注明来源。不要混用证据标签。

## 双语安排与路径

默认根目录`README.md`为中文首页，保留短英文标题；完整英文首页放在`文档/英文说明v1.0.md`或仓库已有约定位置。两页都有语言切换入口，保持模块顺序与当前能力一致。

英文页从子目录链接根目录文件时使用`../`，从子目录引用本目录素材时不要重复加`文档/`。锚点使用稳定的英文短名称，中文与英文页分别检查。

模板中的`{{变量}}`只是待替换字段。没有对应能力、服务、许可或截图时，删掉相应块；不要为了填满模板新造文件和事实。独立英文页尚未完成时不放无效入口。

## 完成判定

检查本地Markdown和HTML的图片、链接、锚点、启动命令、版本及语言一致性。文件路径中允许中文和版本号，网页URL按工具需要编码，不批量改名旧文件。

发布后的证据分三层记录：远程内容及资产存在、GitHub内容渲染、实际浏览器布局与图片显示。前两者不能代替最后一项。浏览器连接失败时如实说明，不标记视觉复核通过。
